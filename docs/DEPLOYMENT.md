# Deployment Guide

## Build

Install dependencies, verify, migrate and build:

```bash
npm run install:all
npm run verify
npm run db:migrate
npm run build
```

The React production output is generated by Vite under `client/dist`.

## Recommended production shape

- React static frontend: Vercel, Netlify, CDN/static host, or served behind your own reverse proxy.
- Node/Express API: VPS/container/managed Node host behind HTTPS.
- Database: managed or well-backed-up MySQL 8+.
- Uploads: persistent object storage; prescriptions should use private storage.

## Environment

Set `NODE_ENV=production`, strong random JWT secrets, the exact frontend `CLIENT_URL`, production MySQL credentials, SMTP settings and provider-specific secrets outside source control.

The development `PAYMENT_MODE=mock` behavior is not a substitute for real production provider settlement. Connect official bKash/Nagad/Rocket/SSLCommerz logic and signature verification before accepting real electronic payments.

## Database rollout

Back up first, run migrations before serving the updated app, and validate the application against a staging copy. Development seed data is blocked by default in production; do not override that guard for a real store.

## Process and reverse proxy

Use PM2, systemd or your container/orchestration platform. Terminate HTTPS at a trusted reverse proxy/load balancer and configure forwarding headers appropriately. Add `/health` monitoring.

## Upload persistence

The included local development folders are convenient but should not be the only copy of production images/prescriptions. Use an object-storage adapter or persistent mounted volume. Private prescriptions require access control and should never be exposed as a public bucket.

## Backups and operations

Schedule database backups, test restores, centralize logs, rotate secrets, patch dependencies, monitor error/latency rates and document incident procedures. Retain audit records according to your organizational and legal requirements.
